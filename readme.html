Detailed Operation of Each Algorithm
This section describes the principle, strategy, and characteristics of each of the 13 implemented solvers.
GreedyConstruction

Principle: Traverses vertices in natural order (0, 1, ..., n-1) and assigns each vertex the smallest color not used by its already-colored neighbors.

Complexity: O(n + m) — very fast but quality depends on vertex order.

Usage: Baseline, initial upper bound, component of other algorithms.

Welsh-PowellConstruction

Principle: Sorts vertices by descending degree before applying greedy coloring. High-degree vertices (more constraining) are colored first.

Complexity: O(n log n + m) — sort + greedy coloring.

Advantage: Significantly improves naive greedy on most graphs.

DSATURConstruction

Principle: (Brélaz, 1979) At each step, selects the uncolored vertex with the maximal saturation degree (number of distinct colors among its neighbors). Ties are broken by maximal total degree.

Complexity: O(n²) — dynamic saturation update.

Strength: One of the best deterministic heuristics; often optimal on sparse graphs.

IDOConstruction

Principle: (Incidence Degree Ordering) DSATUR variant: selects the vertex with the largest incidence degree (number of already-colored neighbors, not distinct colors). Ties broken by total degree.

DSATUR difference: IDO counts colored neighbors (quantity), DSATUR counts distinct colors (quality).

Complexity: O(n²).

RLFConstruction

Principle: (Recursive Largest First, Leighton 1979) Builds one color at a time by forming a maximal independent set: starts from a vertex, iteratively adds the non-adjacent vertex with the most neighbors in the set under construction. Repeats on the remaining subgraph.

Complexity: O(n²) — repeated independent set construction.

Strength: Excellent on dense graphs; often close to optimal.

Smallest-Degree-Last (SDL)Construction

Principle: (Matula & Beck, 1983) Iteratively removes the minimum-degree vertex in the remaining subgraph, recording the removal order. Then colors in reverse order (last removed first).

Complexity: O(n + m) with a bucket queue structure.

Theoretical link: The degeneracy order guarantees χ ≤ k+1 where k is the degeneracy number.

Random Greedy (×10)Stochastic

Principle: Runs greedy coloring 10 times on a random vertex order (different seed each trial). Keeps the best result (fewest colors). On the challenging set, 5 trials are used.

Complexity: O(10·(n+m)) — trivially parallelizable.

Usage: Simple stochastic baseline; explores the vertex-order space.

Simulated Annealing (SA)Metaheuristic

Principle: Starts from an initial coloring (greedy), then explores the coloring space via local moves (recoloring a vertex). Accepts worsening moves with a probability that decreases according to a temperature schedule (cooling).

Key parameters: max_iter=20000 (main pipeline) or 5000 (challenging set), initial temperature=10.0, cooling_rate=0.999, min_temp=0.01.

Strength: Can escape local optima; quality depends on the schedule and allocated time.

TabucolMetaheuristic

Principle: (Hertz & de Werra, 1987) Tabu search for k-coloring: works on conflicts (monochromatic edges). At each iteration, chooses the best non-tabu move (recoloring a conflicting vertex) that most reduces conflicts. Uses a tabu list (adaptive tenure) to forbid immediate returns.

Key parameters: max_iter=1000 (main pipeline) or 5000 (challenging set), tenure = floor(0.6·|conflicts|) + randint(0, 9).

Strength: Very effective at finding a valid k-coloring if k ≥ χ; basis of HEA.

HEA (Hybrid Evolutionary Algorithm)Hybrid (GA+TS)

Principle: (Galinier & Hao, 1999) Memetic algorithm: Population of valid k-colorings (or with conflicts) + GPX crossover (Greedy Partition Crossover) that assembles the best color classes of two parents + Tabucol local search on each child.

Loop: Tournament selection → GPX → Tabucol (ls_iter) → Replace most similar parent if child is better.

Parameters: pop_size=10, max_generations=50, ls_iter=1000. Decreases k while a valid solution is found.

Strength: State of the art for coloring; combines global exploration (GA) and local exploitation (Tabu).

Backtracking (exact)Exact

Principle: Exhaustive search with pruning: tries to assign colors to vertices (Welsh-Powell order: descending degree) via backtracking. Cuts a branch as soon as the number of colors used ≥ best solution found.

Complexity: Exponential in the worst case; fast on small/medium or structured graphs.

Role: Provides proven optimal χ (ground truth) for the benchmark.

CP-SAT (OR-Tools)Exact (CP)

Principle: Models coloring as a constraint satisfaction problem (CSP): variables = color of each vertex (domain 0..k-1), constraints = adjacent vertices ≠ color. Solved by CP-SAT (Google OR-Tools): tree search + constraint propagation + clause learning.

Strategy: Iterates k = 1..upper_bound (greedy); stops at the first k with status=OPTIMAL (continues on FEASIBLE only to seek a better optimum).

Parameters: time_limit=60s, but per-k budget is capped at min(60, 60/k) seconds, so the effective time per k drops below 60s for k > 1. Run only on the challenging subset of instances.

SATExact (SAT)

Principle: Reduction of k-coloring to SAT: boolean variables xv,c (vertex v has color c). Constraints: (1) each vertex has at least one color, (2) at most one color per vertex, (3) adjacent vertices do not share the same color. Solved with a SAT solver (e.g. Glucose, CaDiCaL).

Approach: Incremental (descending) search over k; solved with Glucose3. No native timeout — a hard process-level timeout of 70s is enforced by the runner on the challenging subset.

Strength: Modern SAT solvers are very performant on structured instances; complements CP-SAT. Run only on the challenging subset of instances.

Experimental Findings The statistical anomalies

What the framework revealed on 296+ random graphs (n=60, p≈0.6)
The massive experimentation isolated structurally hard instances where the gap between heuristics and exact optimality is systematic, reproducible, and significant.
37
Isolated "hard" instances
At p≈0.6 (critical density), 37 graphs out of 296 require exclusively backtracking to reach χ. All other solvers (DSATUR, SA, HEA, Tabucol, CP-SAT) remain stuck at χ+1.
+1
Exact one-color gap
On these 37 instances, the gap is systematically 1: χ_heuristic = χ_optimal + 1. No approximate solver crosses this barrier, suggesting a common structural property (hidden clique, critical core, etc.).
p≈0.6
Critical density phase
Difficulty explodes in a narrow window around p=0.6 (G(n,p) with n=60). Outside it, heuristics find the optimum. This phase transition coincides with the expected satisfiability threshold for k-colorability.
⚡
Metaheuristic instability
SA, Tabucol, HEA: highly variable performance depending on density. On hard instances, they converge to local optima (χ+1) without an effective escape mechanism. The fitness landscape shows deep valleys with no gradient toward the global optimum.
0%
Total failure of approximate exacts
CP-SAT and SAT do not reach the optimum on these 37 instances (evaluated on the challenging subset, with the per-k time budgets noted above), while naive backtracking (without sophisticated upper bounds) succeeds. The difficulty appears structural rather than purely computational — though this subset was pre-selected precisely because heuristics failed, so the comparison is not on the full 296-graph corpus.
χ∈[23,28]
Moderate chromatic number
These graphs are not trivial (χ≈n/2) but not extreme either. The gap ω ≤ χ ≤ Δ+1 is tight: ω_lower_bound ≈ 23, χ_optimal ≈ 25–26. The structure blocks just above the clique bound.

The Union / Extract / Compare panel (inside stats.html)

The interactive report (stats.html) has a ⚡ Union button that opens a panel to combine, extract, and compare instances across solvers:

  • Union — select one or more algorithms; the panel computes the union of files where the selected algorithm(s) reached the optimum (or the non-optimal ones), with a per-density breakdown.
  • Compare — the table shows, for each algorithm, its optimal rate, best rate, total colors, total gap, and total time, so solvers can be compared at a glance.
  • Extract — export the selected set of files in two ways:
    • 📋 Copy IDs — copies the run IDs (e.g. 000024) to the clipboard;
    • 📦 Export script — downloads a copy script (copy_optimal_union.sh / .bat, or the non-optimal variants) that copies the chosen JSON files from the source folder to a destination folder. You can set both paths directly in the interface.
Typical workflow

Doctoral research problem

The question is no longer technical — everything works. The question is scientific: which direction turns these anomalies into an original doctoral contribution?
Path 1

New hybrid algorithm targeting hard instances

Design a solver specialized for the p≈0.6 zone that crosses the χ+1 barrier. Hybridize: structure-guided local search (critical core detection, hidden cliques) + adaptive escape mechanism (targeted perturbation, component recoloring).

Path 2

Landscape analysis — Instance Space Analysis

Understand structurally why these 37 instances block all heuristics. Map the instance space (features → difficulty) via Instance Space Analysis (Mersmann et al., EvoCOP): identify the hardness regions, the discriminating features (girth, ω-gap, modularity, k-cores), and model the χ/χ+1 frontier.

Algorithm Selection with symbolic (White-Box) rules

Instead of opaque ML (Random Forest, NN), learn interpretable decision rules (bounded decision trees, rule sets, programming by optimization) to predict the best solver from features. Contribution: explainable selection + theoretical guarantees (regret bound) + zero-dependency deployment.
